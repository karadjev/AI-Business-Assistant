# Подготовка каналов и согласия

Единый Inbox показывает связь диалога с заявками и клиентским идентификатором внутри организации, обработку, ответственного, согласования и доставку. Идентификаторы разных каналов автоматически не объединяются. Для Telegram и WhatsApp согласованный ответ проходит существующие шлюзы доставки. Instagram сохраняет согласованный ответ в Inbox, исходящий транспорт выключен.

Синтетический реестр хранит события для назначения «маркетинговые предложения по услугам». Источник — полученное сообщение клиента, канал, идентификатор и SHA-256 точного текста, время сообщения и регистрации. В тесте команда клиента «согласен получать предложения по услугам» фиксирует согласие, «отзываю согласие на предложения по услугам» — отзыв. Команды сотрудника не считаются согласием. Маркетинговые шаблоны WhatsApp проверяются при постановке и перед доставкой. Отозванная в очереди отправка не возобновляется новым согласием. Статус неизвестной доставки обрабатывается по действующему регламенту без автоматической повторной отправки. Отправка, уже переданная провайдеру до регистрации отзыва, необратима. История тестового согласия следует сроку хранения исходного сообщения и диалога.

Перед реальной проверкой оператору нужен отдельный допущенный контур и выделенные тестовые аккаунты. Telegram — бот, тестовый пользователь и разрешённый HTTPS webhook. WhatsApp — тестовые Meta App и WABA, зарегистрированный тестовый номер и действующая проверка провайдера, шаблонов и финансового допуска при бюджете 0 ₽. Instagram — тестовый профессиональный аккаунт, одобренные разрешения Meta для сообщений и подписка на webhook. Данные доступа передаются через серверное хранилище секретов. Текущие режимы провайдеров не изменяются. Для реальных маркетинговых операций нужен отдельно допущенный доказуемый источник согласия и отзыва. Синтетические события не пригодны для допуска живой отправки.
