# Audit / receipts retention — предложение 10В, НЕ УТВЕРЖДЕНО

Ни один срок ниже не является действующей политикой. Этот этап не добавляет удаление минимальных receipts, source history, security или financial audit. Существующая минимизация временных import artifacts и hold продолжают действовать по ранее принятой политике.

## Вопросы для отдельного решения владельца продукта

| Класс | Варианты для обсуждения | Условие до реализации |
|---|---|---|
| Минимальный import receipt: digest/request key/status/actor/time/summary | Хранить весь срок магазина либо архивировать после 12/24 месяцев | Определить горизонт повторов и гарантию idempotency; удаление ключей не должно повторно применять импорт |
| Source handoff snapshot / catalog events | Полная online история либо архив после 12/24 месяцев | Сохранить расследование происхождения цены/остатка, actor и связь с операцией |
| Security audit | Отдельный срок, например 12/24 месяца, либо без удаления до утверждения | Уточнить требования оператора, расследований, доступа и персональных данных |
| Financial admission / budgets / receipts | Отдельное решение; числовой срок не предлагается | Проверить финансовые обязательства и доказательства provider reconciliation; unknown delivery/cost не считать завершёнными |

Варианты 12/24 месяцев — гипотезы для согласования, не нормативная рекомендация. Применимые обязательства здесь не исследовались. Нельзя использовать один TTL для всех классов.

Нужно согласовать: начало отсчёта; минимальные поля; online/archive режим; владение архивом и доступ; legal/operator hold; запрос удаления магазина; backup retention; immutable evidence; восстановление; storage budget; отдельный approval для миграций/worker. Hold имеет приоритет и не восстанавливает ранее минимизированные артефакты.

До этого решения остаётся прежнее поведение: receipts/audit сохраняются без нового срока удаления. Не добавлять DELETE/CASCADE/partition drop или автоматический purge под видом оптимизации истории.
