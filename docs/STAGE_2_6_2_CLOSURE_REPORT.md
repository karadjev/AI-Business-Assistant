## Потребность в запчастях

Владелец задаёт `part_rule` на услуге через существующий `POST /operations/services/config/offerings`. Сохранение использует действующую проверку владельца и revision услуги. Правило содержит состояние, при необходимости OEM и количество, а также опциональные ограничения по марке, модели, двигателю и году. Совместимость и свежесть остатков по-прежнему проверяются по данным tenant.

| Состояние | Действие |
| --- | --- |
| REQUIRED | Используются OEM и количество из правила, затем проверяются совместимость и остаток. |
| OPTIONAL | Требуется явное решение. При выборе детали применяется утверждённый OEM. |
| NOT_REQUIRED | Используется сервисная запись без резерва товара. |
| UNKNOWN | Возвращается запрос на уточнение или диагностику. Подтверждаемая заявка отсутствует. |

Несовпадение автомобиля с правилом и некорректная сохранённая политика дают UNKNOWN. Автоматический запрос без правила получает UNKNOWN. Ранее поддержанные явно подготовленные сотрудником запросы без настроенного правила сохраняют прежний контракт. При наличии правила оно имеет приоритет.

## Ответ после решения

Миграция 00026 связывает событие существующего Order API с завершённой задачей по tenant, диалогу, ключу идемпотентности и точному содержимому предложения. После успешной записи события в этой же транзакции создаётся дочерняя задача Business Manager для текущей версии заказа. Отдельная очередь или система бронирования не вводятся. Повтор подтверждения возвращает сохранённый результат Order API. Повтор события на ту же версию не создаёт второй задачи.

После получения lease worker читает текущий статус заказа, фактическое бронирование, резерв и позиции. Ответ содержит статус и версию, название услуги, слот, часовой пояс, специалистов при наличии и сохранённые цены. Если общая сумма не закреплена в заказе, ответ её опускает. Успешный ответ возможен только при подтверждённом бронировании и, для hybrid, активном резерве. Отказ, отмена и истечение дают отдельные сообщения. Текст и данные сохраняются в результате дочерней задачи и доступны через действующий API задач. Ответы клиенту по внешним каналам не отправлялись.

Чтение ограничено lease, исходной задачей, tenant и связанным событием. Роли и политики доступа к существующим бронированиям сохранены. Ошибка чтения проходит действующий механизм retry. Worker выполняет чтение и сохранение результата задачи. Изменение заказа и запасов остаётся за существующим авторизованным переходом.

## Приёмка

| Проверка | Статус | Результат |
| --- | --- | --- |
| Правила и неопределённость | PASS | Unit покрывает четыре состояния и несовпадение автомобиля. Реальный API проверил автоматические REQUIRED, NOT_REQUIRED и UNKNOWN. |
| Подтверждение, отказ, отмена и повтор | PASS | Проверены действующие Order API, одна запись результата при повторе подтверждения, отсутствие резерва до подтверждения, отказ и отмена. Повторное событие на ту же версию не создало дубликат задачи. |
| Недостаток товара и изменение цены | PASS | PostgreSQL отклонила подготовку при недостатке. Изменение цены заблокировало подтверждение без удержаний. |
| Ответ Business Manager и restart | PASS | Подтверждение при остановленном worker оставило задачу в очереди. После запуска сохранён ответ с актуальным статусом, ценой детали и резервом. |
| Истечение и ошибка чтения | PASS | Сбой чтения PostgreSQL перевёл задачу на retry. Повтор сохранил подтверждённый результат. Истечение освободило товар и слот, worker сохранил отмену с expired. |
| Tenant isolation и регрессия | PASS | Чужой диалог и чтение без lease отклонены. FORCE RLS на 61 таблице, полная PostgreSQL suite и миграция 00026 up/down/up прошли. |
| Браузерное подтверждение текущего снимка | PASS | Новый targeted тест прошёл с финальными API и worker и совпадающим source guard. |
| Отдельная доставка конечному клиенту | NOT RUN | Проверена выдача финального ответа через авторизованный API задач. Отдельный клиентский или внешний канал не проверен. |

В полном браузерном прогоне все 23 сценария прошли. Итоговый source guard вернул FAIL из-за изменения исходников во время прогона. Финальный focused Chromium прошёл с совпадающими SHA. Исторические отчёты и этот FAIL сохранены. Go tests, race, vet, API/worker builds, Next.js build, lint и typecheck прошли.
