# Store onboarding — 10А

Мастер `/dashboard/onboarding?org=<existing organization>` доступен владельцу через раздел «Настройка магазина». Без магазина показывается ссылка на существующую страницу явного создания организации. Мастер не создаёт tenant автоматически и не вводит новую систему пользователей/магазинов.

Пять шагов: информация → единый каталог → mapping/preview → каналы → готовность. Название обновляет существующую organizations.name. Дополнительный store_profiles связан PK/FK с organization_id и хранит описание, информационную категорию бизнеса, адрес, часы, контакты, доставку, оплату, возврат и инструкции для ИИ. Версия защищает от конкурентного сохранения. Техническая специализация прежнего organizations.business_type=electronics не переопределяется свободным текстом профиля; демонстрация — электроника. Никакого геокодирования/внешней проверки контактов нет.

| Статус | Значение |
|---|---|
| NOT_STARTED | Профиль ещё не создан |
| IN_PROGRESS | Профиль сохранён, настройка продолжается |
| CATALOG_READY | Импорт подтверждён либо owner явно подтвердил наличие каталога |
| CHANNELS_PENDING | Owner перешёл к настройке каналов |
| READY_FOR_REVIEW | Каталог есть, нет ошибочных pending previews, есть настроенный mock-канал |
| ACTIVE | Owner явно подтвердил READY_FOR_REVIEW; локальная настройка завершена |

ACTIVE **не включает live**, не меняет kill switches, budgets, credentials, outbox или financial admission. API/UI показывают LIVE_DISABLED/LLM_BUDGET_ZERO/WHATSAPP_BUDGET_ZERO независимо от статуса. Draft товары требуют отдельной публикации через прежний каталог. Для переходов после профиля нужен непустой каталог; ошибки pending preview нужно исправить либо отменить импорт. Существующие каналы настраиваются через прежние mock-страницы по явному действию владельца.

Профиль — owner configuration data. Дополнительные инструкции сохраняются, но не исполняются как код и не дают прав изменять цены/consent/бюджеты/статусы провайдера. Новый live LLM prompt/provider не подключён; integration с будущим store-policy tool требует отдельного review. Каталог уже доступен общему существующему агенту после публикации товара.

Ручное управление MANUAL товарами остаётся в прежнем UI/API. Excel работает с теми же products/product_variants/inventory. Кнопка1С отключена с отметкой «В разработке». Live controls не добавлены. Staff не может читать/менять профиль или импорты владельца; прежние разрешённые staff order/reservation операции сохранены.

API под `/api/v1/organizations/{id}`: GET/POST `/onboarding`, PUT `/store-profile`. Мутации требуют действующей session, Origin, CSRF, tenant owner, expected_version и подтверждение для смены стадии. Наименования полей и пределы — OpenAPI0.10.0. В мастере используются только существующие memberships, а не organization_id из загруженного файла.
