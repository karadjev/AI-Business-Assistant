# Catalog Health Score · catalog-health-v1

Backend `catalog.Health`, без LLM. Единица расчёта — неархивный вариант товара; products/active/available в overview отдельно считаются по уникальным карточкам. Без вариантов score=NULL («Нет данных»), не 0. Одного варианта достаточно для определённой оценки; размер выборки показан рядом. Это completeness/risk indicator, не вероятность продаж и не разрешение live.

`R(n,d)=floor(100*clamp(n,0,d)/d)`; при d=0 фактор нейтрален (100), отсутствие наблюдения показывается отдельно. Итог `floor((20*C + 20*P + 15*K + 25*F + 10*S + 10*I)/100)`.

| Фактор | Вес | Воспроизводимое определение |
|---|---:|---|
| C полнота |20|Доли вариантов с непустыми description, brand и хотя бы одной характеристикой; name/SKU уже обязательны в модели|
| P цена |20|Доля вариантов с price_amount>0; RUB/неотрицательность обеспечивают прежние constraints|
| K известный остаток |15|Дата сверки задана и не из будущего|
| F свежесть |25|Доля FRESH согласно tenant policy на timestamp транзакции|
| S источники |10|`R(total - conflicts,last total variants)`; conflicts — строки последнего доступного preview, с ограничением диапазона|
| I импорт |10|Доля строк последнего доступного import preview без errors/duplicates; FAILED workbook считается одной ошибочной единицей. Без импортов/после минимизации наблюдения нейтральны|

Последний preview выбирается по created_at среди неминимизированных jobs. История/score не выдают старые импортные ошибки за текущие неразрешённые конфликты каждой карточки. UI явно называет область «последний импорт», показывает время оценки и число вариантов. Конфликт не разрешается изменением score.

Unit cases: empty, perfect=100, incomplete=20, половинные факторы=50, saturation=0. Integration проверяет реальные DB rows и политику. Freshness/role/price/reservation/financial gates независимо проверяются backend.
